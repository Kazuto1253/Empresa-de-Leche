# Contribuir a Ecoláctea Digital

## Antes de desarrollar

1. Lee `README.md`, `docs/ARCHITECTURE.md` y `docs/GIT_WORKFLOW.md`.
2. Revisa tus RF, dependencias y pruebas en el Excel de ejecución.
3. Confirma que trabajas en tu rama personal, nunca en `main`.
4. Si una regla está marcada como pendiente, no inventes el valor.

## Criterio mínimo de terminado

Un cambio está listo para revisión cuando:

- respeta Clean Architecture y los módulos existentes;
- implementa permisos en UI y API cuando corresponda;
- conserva errores y validaciones comprensibles;
- incluye pruebas del caso válido, inválidos y límites pertinentes;
- no introduce secretos, rutas personales ni archivos generados;
- actualiza trazabilidad y documentación afectadas;
- puede demostrarse en las plataformas comprometidas.

## Pull Requests

El título debe mencionar el RF o propósito principal. La descripción debe explicar alcance, pruebas, evidencia, dependencias y pendientes. Usa la plantilla del repositorio y solicita revisión a otro integrante.

## Autoría

Cada integrante debe configurar su identidad Git real. No se reescriben commits para simular participación y no se comparte una misma identidad entre autores.
