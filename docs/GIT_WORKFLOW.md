# Flujo Git Futuro

Esta tarea no publica nada en GitHub. Cuando la base sea aprobada, el flujo recomendado será:

1. El coordinador define `main` como base estable.
2. Desde `main` se crean las ramas:
   - `integrante-1`
   - `integrante-2`
   - `integrante-3`
   - `integrante-4`
3. Cada integrante desarrolla sus RF asignados en su rama.
4. Cada integrante ejecuta pruebas antes de publicar.
5. Cada integrante hace push de su rama.
6. Cada integrante abre Pull Request hacia `main`.
7. El coordinador revisa, pide ajustes si corresponde y acepta el merge.

Nadie debe trabajar directamente sobre `main`.

No cambiar la asignación de RF del Excel validado.
